# Luma 0.2.2 code review — October 5, 2026

This was a time-bounded review of the desktop Rust bridge, media-core indexing and history, Node media server and release cache, Android shell and pairing, and Svelte playback/UI integration. Three agents and the primary reviewer split the work. This is not a complete penetration test, a certification, or a guarantee that the application is free of vulnerabilities.

## Confirmed findings and fixes

- **Stale media identity:** integer IDs can be reused after deleting catalog rows. Each computer file now has a persistent UUID; catalog, episode and Continue Watching responses carry the correct file UUID. Playback resolves that UUID without falling back to another title. Old entries may verify their exact existing file ID but cannot remap themselves to a different file by title. A missing or mismatched UUID fails closed.
- **Signed URL identity:** media and subtitle URLs previously accepted signatures tied only to the row ID and expiry. Playback and casting signatures now also depend on the current UUID. Deleting a file and reusing its numeric ID cannot redirect an old signed URL to its replacement. Legacy row-only signatures are rejected.
- **Stale destructive actions:** moving and permanently deleting computer titles now require the UUID to match the requested row. A stale card cannot move or delete a different file merely because its integer ID was reused.
- **Extras leaking into history:** bonus clips were excluded from the catalog but could still affect recommendation seeds, Continue Watching, playback history, or series watched boundaries. These paths now exclude extras; two regression tests cover this behavior.
- **Unbounded sidecar allocation:** external subtitles were read into memory before checking their size. Desktop and Android now check size before reading and cap reads at 8 MiB plus one byte, including a file that grows during the read.
- **Dependency advisory:** updated `source-map-js` to address the high-severity indexed-source-map denial-of-service advisory reported by npm audit. The media-server production dependency audit reported no vulnerabilities.
- **Build while development is open:** Windows preparation now leaves byte-identical runtime executables and DLLs untouched, avoiding overwriting files loaded by the development app.
- **Android branding:** the existing reduced symbol now has margins in adaptive launcher and splash resources. Circular and rounded mask previews were checked; actual launcher rendering can vary by Android version and launcher.
- **Version display:** the mobile bootstrap previously returned a hard-coded old version. It now uses the package version, matching the desktop/Android 0.2.2 build configuration.
- **Mobile subtitle loading:** remote text tracks now enable anonymous cross-origin loading, and automatic selection waits for the mobile track elements to render. The Agency S01E01 was inspected: both embedded English SubRip tracks were detected and the first was converted to WebVTT. Rendering on the user's phone still requires validation.

## Validation

- Frontend type/component validation: zero errors; three existing `corner-shape` compatibility warnings.
- Script regression suite: 49 passing tests, covering artwork caching, favorites, library menus/identity, mobile command recovery, pairing, transcoding preferences, release caching and routing.
- Media-server suite: 14 passing tests, including actual FFmpeg output, range serving and HLS behavior.
- Media-core suite: 24 passing tests, including UUID migration/reuse, moving files, episode identities, extras, progress and subtitle discovery. Identity guards have an additional regression assertion.
- Desktop Rust suite: 25 passing tests and two intentionally ignored live-service tests, including actual embedded-subtitle conversion and the sidecar read limit.
- Recommendation tests and UUID-scoped media-signature tests passed. Some live service tests require credentials/network and are deliberately not part of the offline suite.
- Packaging checks include the real mobile frontend startup test, APK signature verification and installer generation. A successful package build does not replace testing on a physical phone.

## Important remaining work

- **Trust your LAN.** Pairing/control currently use HTTP with bearer tokens and signed media URLs. Traffic is not encrypted; an attacker able to observe/intercept the network can obtain a token and replay permitted operations. Do not expose the bridge to the Internet or use it on public/untrusted Wi-Fi. TLS/certificate pinning and independent per-device revocation remain necessary for a production release.
- **Stream changes can require retry.** The current mobile HLS switch closes the prior stream before preparation of the replacement finishes. A preparation failure can therefore interrupt playback; saved position is retained, but seamless rollback is not implemented.
- **Phone-only file identity** still uses the older local index/hash path, separate from computer UUID identity. It needs the same persistence guarantees before production.
- **Subtitles:** embedded text tracks from the computer can be converted; image-based PGS/VobSub tracks and embedded tracks in phone-only files do not have complete mobile rendering support.
- **Dependencies:** the full npm audit still reports three low-severity development dependency findings involving SvelteKit/adapter-static/cookie. The suggested upgrade crosses major versions and was not forced into this maintenance release. Rust/Android dependencies have not undergone a comprehensive advisory scan.
- **Device validation:** real Galaxy A02s performance, every codec/subtitle combination, launcher caching, casting targets and hostile-network scenarios have not been exhaustively tested. The APK is debug-signed and is distributed as a preview.

Personal media, local credentials, caches, signing keys and unrelated workspace projects are excluded from the Git commit and release assets.
